# R3-C9 快照规范化摘要可复算

日期：2026-10-21
任务：OM-R-C9
目标：元数据快照保存规范化摘要，提供校验点；旧快照可读取并明确标记 legacy，不伪造原摘要。

## 实现

- `V18__snapshot_canonical.sql`：`meta_snapshot.canonical_sha256 char(64)`；旧行保持 NULL。
- 同步：在保存原始 `sha256` 的同时，把资源 JSON 解析为对象树后按 key 排序序列化，计算 `canonical_sha256` 一并入库；原始摘要不变。
- `GET /onto/datasources/{id}/snapshots/{snapshotId}/verify?spaceId=...`（`datasource.read`）：
  - 重新从 `resources` 规范化并计算；
  - 返回 `sha256/canonicalSha256/recomputedSha256/legacy/matches`；
  - 旧快照 `legacy=true, matches=false`，但仍给出 `recomputedSha256`，可人工复核。
- 快照仍禁止 UPDATE/DELETE（既有 immutability trigger 不动）。

## 验证

```powershell
mvn ... "-Dtest=P3MappingTest#snapshotCanonicalDigestIsRecomputableAndLegacyIsExplicit" test
# 通过：新快照 matches=true 且 canonical==recomputed；插入 legacy 行后 legacy=true、matches=false、recomputed 非空
mvn ... "-Dtest=P3MappingTest" test
# 16 项通过
```

Flyway 已应用到 V18；后端全量 **419 项 0 失败**（21:16）。

## 限制

- 规范化摘要只覆盖 `resources`（快照内容），不覆盖 `captured_at` 等元数据。
- 前端未增加"校验"按钮；接口已可供验收脚本/后续页面调用。
