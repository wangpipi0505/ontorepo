# C8 独立审核前端整改与 IAM 实现验证

日期：2026-10-21。范围：独立审核 C12 的现有界面缺口，以及用户明确新增的“可自定义角色及权限的完整管理体系”。修改本工程 `web/` 与本轮证据；未执行 Maven、直接数据库写入、后端重启或历史证据改写。初始组件阶段未生成 OpenAPI；后续在根代理导出真实契约后生成并验证，见末节。

## 已落地的界面行为

1. 新增 `/spaces/:spaceId/conflicts` 独立冲突页及导航。复用服务端草稿检查，四类分组分别呈现错误与警告；关联实体索引和冲突在前后修订校验包围下读取。属性链接携带所属类，规则/约束/策略展开关联详情，操作高亮、对象树选中；只读用户可定位，缺失标识明确提示，绝不假造链接或自动打开写入表单。
2. `FrozenOperationTrialPanel` 供候选页及规则页共享。规则入口先选择冻结候选，仅列候选自身绑定目标规则的 RULE_CHECK/SCORING 操作。提交只有 `operationId` 与业务输入；不传 `ruleIds`，不执行草稿，不回退草稿操作清单。候选 ID、SHA-256 与修订同屏，切换/离开上下文后丢弃迟到结果。
3. 用例页新增批量冻结验收入口，与发布向导共享 `CandidateTestsPanel`。校验响应摘要、区分零用例、VIEWER/缺少 test.execute 默认拒绝；先解除提交锁再通知父页面刷新，避免组件卸载遗留 busy。409 通知发布向导锁住原候选。发布页按后端阶段限制 validate/review/tests，READY_TO_COMMIT 不重跑这些前序门禁。
4. 401 保留原有全局清除会话/空间和跳转行为，增加只消费一次的中文原因提示。匿名登录失败、主动退出不误报过期；旧令牌的迟到响应不注销新会话。
5. 系统用户、角色与权限、管理审计分别为独立路由。用户编辑、密码重置、角色编辑与分组权限选择拆分组件。角色编码不可改；内置角色只读；有关联用户的角色不能从界面删除。用户变更保留打开时 revision，冲突保留输入并锁定提交，关闭刷新后重新编辑。密码不放进列表、审计或浏览器存储，重置需明确确认，成功清除输入。
6. `auth/permissions` 是会话能力来源，登录及路由进入重新取得权限；无结果/读取失败默认关闭能力。导航、路由、页面写入与独立 execute/create 按钮使用相应代码。系统管理员仍需要原空间身份；OWNER 豁免和数据守卫不被功能权限替代。业务组件单测通过显式授权 fixture 保留原测试前提，生产默认拒绝未放宽。
7. C11 抽取界面将 confidence 明确显示为“规则先验分值”，说明不是当前证据正确概率；METADATA_ONLY 来源显示未读取实例样例及服务端原因。
