## 2. 逐项验收与剩余

### IA-01 一级导航
验收：未进入本体也能看到 本体建模/知识与数据/测试与服务封装/数据溯源审计/系统管理；账号只在右上角。
状态：完成。剩余：无。

### IA-02 全局路由
验收：`/data`、`/delivery`、`/trace` 可直接访问；`/spaces/:id/data|delivery|trace` 重定向并保留 `spaceId`。
状态：完成。剩余：无。

### IA-03 本体空间管理表
验收：名称/编码、领域、状态、规模、关系/规则、版本、校验/映射、更新时间、行内动作；点击行进入建模。
状态：完成。剩余：
- “更多”仍是原生 `<details>` 浮层，未统一为设计系统浮层；
- 版本/校验依赖概览接口，读取失败时只显示错误与重试。

### IA-04 画布主区
验收：画布高度随视口、右侧属性栏独立滚动、画布为默认主视图。
状态：完成（基础）。剩余：
- 节点少时大片空白，未做自动 fit/紧凑布局；
- 未做画布内对象搜索/定位；
- 小屏画布降级未单独验收。

### IA-05 建模容器
验收：8 个页签；同一时刻只有一个页面实例；规则/冲突/策略/操作为表格视图。

验收：新建对象、修改对象、新建关系可撤销；撤销使用当前 `draftRev`；失败可见。

## 3. 依赖与阻塞

| 项 | 条件 | 影响 |
|---|---|---|
| 全局聚合性能 | 目前按可见空间循环调用各服务 | 空间数量大时变慢；需改为一次 SQL 聚合 |
| 全局溯源上限 | 单类约 300 条 | 需要游标/分页设计 |
| 撤销范围 | 服务端无通用反向接口 | 删除类操作暂不可撤销，需草稿快照恢复 |

## 4. 更新规则

1. 每次 IA/视觉提交必须更新本表对应行的状态、提交号、剩余项。
2. 只有验收标准全部满足才能写“完成”；否则写“部分”并列出剩余。
3. 回复用户时必须引用本表 ID，不得用“已完成”掩盖“部分”。
4. 新增事项追加新 ID，不覆盖历史。
